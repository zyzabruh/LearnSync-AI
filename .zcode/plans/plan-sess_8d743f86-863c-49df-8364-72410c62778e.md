# Amélioration de LearnSync-AI — Plan en 4 phases

Ordre choisi : d'abord les bugs de données (valeur utilisateur immédiate), puis le refacto (sur code corrigé), puis les fonctionnalités calendrier et fiabilité. i18n décalée (français hardcodé conservé). Un commit par sous-phase, tests unitaires à chaque étape.

## Phase 1 — Bugs d'intégrité des données (migration Room 10→11)

**1.1 Préserver l'historique de révision à la régénération** (bug le plus grave : streak/stats remis à zéro)
- Migration 10→11 dans `LearnSyncDatabase.kt` :
  - `review_logs` : ajout d'une colonne `courseId` indexée (backfill via JOIN sur flashcards existantes) et **recréation de la table sans FK CASCADE vers flashcards** (`cardId` devient une simple colonne indexée) → les logs survivent à toute suppression de cartes
  - Nouvelle table `review_sessions` (id, courseId nullable, startedAt, endedAt, cardsReviewed) — servira aux stats (3.2) et au calendrier
  - Nouvelle table `tombstones` (entityType, entityId, deletedAt, PK composite) — servira à la sync (1.2)
- `replaceCourseContentAtomically` : avant suppression, matcher anciennes/nouvelles cartes par question normalisée (trim + lowercase + collapse espaces) et reporter l'état FSRS (easeFactor, difficulty, repetitions, lastReviewedAt) sur les nouvelles cartes identiques
- Activer `exportSchema = true` pour les migrations futures

**1.2 Suppressions propagées à la sync Firestore (fin des cartes zombies/doublons)**
- Les suppressions dans les repos (flashcards/QCM custom, cours) insèrent un tombstone
- `FirestoreSyncManager.syncUp` : suppression des docs tombstonés sur Firestore puis purge des tombstones ; `syncDown` : ignore les entités distantes présentes dans les tombstones (la suppression l'emporte)
- Correction du bug d'ordre dans `syncWithCloud` (`LearnSyncViewModels.kt` l.719-828) : fusionner les préférences distantes **avant** l'upload du résultat

**1.3 Notation transactionnelle**
- Nouvelle méthode `@Transaction` (update flashcard + insert review_log + update review_session) exposée par le repo ; supprime le risque d'état FSRS incohérent au crash. Fusionne au passage les doublons `reviewCard`/`rateCurrentCard`

**1.4 Cartes dues vivantes**
- `RepositoriesImpl.getDueFlashcards` : `flatMapLatest` sur un ticker 60 s → la requête repart avec un `now` frais (les cartes re-dues « Again +10 min » apparaissent sans recréer le ViewModel)

**1.5 Erreurs critiques surfacées**
- `CourseContentStorage.readExtractedText` retourne un résultat typé succès/échec ; la génération IA s'interrompt avec un message clair si le texte extrait est vide/illisible (fini la génération sur document vide)
- Dé-silencer les `catch (_:` sur : upload cloud, deleteCourseInCloud, init ViewModel (message d'état) — Firebase optionnel reste silencieux

**Tests** : Robolectric pour la migration 10→11, la préservation d'historique à la régénération et la transaction de notation ; extension de `FirestoreSyncManagerTest` (tombstones, ordre prefs).

## Phase 2 — Refacto architecture

**2.1 Conteneur DI manuel** : `AppContainer` dans `LearnSyncApplication` (DB, 8 repos, clients IA, sync managers, TtsController) — plus d'instanciation dans le ViewModel. Pas de Hilt (mono-module, reste léger et réversible).

**2.2 Découpage du ViewModel de 1 168 l. en 5 ViewModels par feature** :
- `LibraryViewModel` (cours, import, génération/régénération, CRUD custom, export)
- `ReviewViewModel` (session, notation, TTS, refresh widget)
- `ProfileViewModel` (préférences, profils IA, Gemma, auth)
- `SyncViewModel` (cloud + calendrier Android)
- `SearchViewModel` (recherche globale)
- `LearnSyncNavigation` collecte par feature ; les écrans restent des composants « dumb » (pattern state + callbacks inchangé). Composant commun bottom-bar/NavigationRail pour supprimer la logique dupliquée.

**2.3 TTS hors de la couche UI** : `TtsController` (init paresseux, speak/stop, file d'attente, auto-speak, release) possédé par `ReviewViewModel` ; `ReviewScreen` ne gère plus le moteur `TextToSpeech`.

**2.4 Découpage des fichiers géants** (pur déplacement, comportement identique) :
- `ProfileScreen.kt` (1 658 l.) → ProfileScreen + AiProfilesSection + PreferencesSection + SyncSection + AiProfileEditDialog
- `CourseDetailScreen.kt` (1 107 l.) → CourseDetailScreen + onglets Résumé/Flashcards/QCM + dialogs

**2.5 Dépendances** : Compose BOM → dernière stable, Navigation/Lifecycle à jour ; suppression de DataStore (jamais utilisé) ; migration des versions en dur vers `libs.versions.toml` ; nettoyage des blocs commentés.

## Phase 3 — Plan de révision / Calendrier

**3.1 Prévision de charge future** : `SpacedRepetition.forecastSchedule(card, horizonDays)` (simulation multi-sauts rating Good) → la grille mensuelle affiche échéances réelles (pastille pleine) **et** répétitions prévues J+3/J+7/J+30… (pastille contour), avec légende ; distinction retard (rouge) / aujourd'hui / futur.

**3.2 Marqueurs d'historique + vraie durée d'étude** : le calendrier marque les jours réellement révisés (depuis `review_logs`/`review_sessions`) ; `StatsScreen` utilise la durée réelle des sessions au lieu de la somme des `responseTime` (sous-estimée).

**3.3 Sync agenda Android corrigée** (`CalendarHelper.kt`) :
- Écriture des événements **futurs** (charge prévue par jour, horizon réglable, défaut 14 jours) au lieu des seules cartes en retard massées à 09:00
- Mise à jour/suppression des événements obsolètes après révision (réutilise `deleteCalendarEvent`, aujourd'hui sans appelant) ; nettoyage des événements orphelins à la suppression d'un cours
- Heure/durée/rappel réglables (nouvelles préférences ; défauts : heure = reminderTime, 30 min, rappel 15 min)

**3.4 Deep link widget** : `MainActivity` lit l'extra `navigate_to="review"` et navigue vers l'onglet Réviser.

## Phase 4 — Fiabilité cloud/IA + OCR

**4.1 Sync automatique** : après génération réussie → `OneTimeWorkRequest` de sync (contrainte réseau, backoff) ; option sync périodique quotidienne ; retry/backoff sur `batch.commit()`/`get()` ; état de sync visible dans l'UI (dernière sync, badge « en attente »).

**4.2 OCR des PDF scannés** : détection « PDF sans couche texte » → proposition d'OCR avec progression annulable : rendu des pages en bitmaps (PdfBox, pages/taille plafonnées) + ML Kit Text Recognition on-device (variante unbundled via Play services pour limiter la taille de l'APK, message de repli si indisponible), fusion du texte puis génération IA normale.

**4.3 Divers IA** : `maxTokens` — la première tentative utilise la valeur configurée (262 144) avant les fallbacks ; retrait des logs de debug endpoints/modèles.
