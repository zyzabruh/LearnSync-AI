Plan d'amélioration LearnSync AI — 5 axes, exécutés et testés un par un (commit + push à chaque étape).

## 1. Sécurité (priorité, rapide)
- **Keystore exposé** : `app/keystore.jks` et ses mots de passe (`android123`) sont committés en clair dans `build.gradle.kts` et visibles sur GitHub public. Actions : retirer le fichier du dépôt, l'ajouter au `.gitignore`, charger les mots de passe depuis `local.properties` (fourni hors repo). ⚠️ À noter : le fichier reste dans l'historique GitHub — je vous recommanderai de changer le mot de passe du keystore (ou de le régénérer) car il a déjà été exposé.
- **Clés API IA en clair** : elles sont stockées en clair dans Room et partent dans la sauvegarde cloud Android (`data_extraction_rules.xml` inclut tout). Actions : chiffrer les clés avec Android Keystore (AES-GCM) via un petit `ApiKeyCipher` appliqué dans les repositories de préférences/profils IA (transparent pour le reste de l'app) ; exclure les données chiffrées des backups inutiles. Les cours restent sauvegardables.

## 2. OCR pour PDF scannés (vos cours de physique scannés)
- Aujourd'hui un PDF sans couche de texte est rejeté avec une erreur. Actions : ajouter ML Kit Text Recognition (OCR sur l'appareil, gratuit, hors-ligne, ~4 Mo d'APK en plus) ; dans `DocumentParser.parsePdf`, si aucun texte n'est extrait, rendre les pages en bitmap via `PdfRenderer` et les passer à l'OCR (limite 30 pages pour la performance), avec un message de progression « OCR en cours ».

## 3. Fiabilité IA
- **Annulation** : la génération est aujourd'hui inarrêtable (jusqu'à 5 min). Actions : rendre l'appel OkHttp annulable (`enqueue` + `suspendCancellableCoroutine`), exposer un `Job` dans le ViewModel et un bouton « Annuler » dans la bannière de génération ; une annulation volontaire ne marque pas le cours en erreur (retour à l'état précédent).
- **Vitesse** : les documents longs sont traités un chunk à la fois (`Semaphore(1)`) → passer à 2 en parallèle (≈2× plus rapide), tout en gardant un débit raisonnable pour les quotas gratuits.

## 4. Choix du nombre de flashcards / QCM / astuces
- Le réglage existe déjà (Profil → flashcards/QCM en auto/custom) mais est invisible au moment où on en a besoin. Actions : ajouter une feuille « Options de génération » dans `CourseDetailScreen` (nombre de flashcards, de QCM, d'astuces mnémotechniques, ou auto) qui s'ouvre avant « Régénérer », en réutilisant les préférences existantes — zéro nouvelle table ni migration.

## 5. Architecture (en dernier, plus gros diff)
- Découper `LearnSyncViewModel` (725 lignes) en ViewModels par fonctionnalité (cours, génération IA, révision/quiz, sync/profil) ; comme l'ensemble du câblage passe par `LearnSyncNavigation.kt`, la refactorisation est concentrée sur ce fichier.
- Centraliser dans `strings.xml` uniquement les nouveaux textes (une internationalisation complète des 5 000 chaînes existantes serait un chantier séparé).

## Non concerné
- Firebase/sync cloud : laissé tel quel (désactivation gracieuse déjà en place) puisque vous l'utiliserez peut-être plus tard.

## Vérifications à chaque étape
`gradlew compileDebugKotlin` + tests unitaires existants + nouveaux tests ciblés (chiffrement round-trip, détection OCR, annulation) ; commit et push GitHub à chaque axe terminé.
